## Agentic OS — "no funciona nada" (5 bugs, no 1)

Sesión larga de depuración. El usuario reportaba la UI vacía ("SIN LECTURA", "NO HAY DATOS PARA GRAFICAR") y el chat inutilizable. No era un bug: eran **cinco que se combinaban**.

### Diagnóstico real (con evidencia)

1. **SSE (causa raíz).** `app.py` nunca definía `protocol_version`, así que el servidor hablaba **HTTP/1.0**. El SSE mandaba `Connection: keep-alive` **sin `Content-Length` ni `Transfer-Encoding`** → un navegador no puede delimitar el cuerpo y el `EventSource` falla al instante. Python sí lo leía (un socket crudo ignora el framing) → por eso "en backend funciona pero en el navegador no".
2. **Chat → `503 unknown_outcome` a los 5 s.** Usaba el endpoint síncrono. Al pasar a `prompt_async` el BFF **seguía fallando y además mentía**: devolvía `202` con `text: "{}"` mientras el upstream había rechazado el mensaje con **400 `Missing key at ["model"]["modelID"]`** (mandaba `model:{id,...}`; el `serve` exige `{providerID, modelID}`).
3. **CSRF.** `/auth/me` rotaba el token en **cada** request; el `onerror` del SSE lo llamaba → el token del cliente quedaba inválido → **todo POST daba 403**.
4. **Login.** Solo aceptaba `Origin: 127.0.0.1:8797`; desde `localhost` → **403** y la UI quedaba en placeholders.
5. **Cupo SSE.** `MAX_CLIENTS = 2`; conexiones muertas ocupaban el slot ~15 s → 429.

### Fixes aplicados

- `protocol_version = "HTTP/1.1"` + SSE con `Transfer-Encoding: chunked`; **auditados todos los demás endpoints** para que manden `Content-Length` (con HTTP/1.1 es obligatorio o el navegador se cuelga).
- Chat: mapeo del modelo a `{providerID, modelID}`, resolución desde la sesión, `_default_model()` de respaldo, **no devolver 202 si el upstream rechaza**, y capturar `ApiException` (el 409 del modelo subía como 500 genérico).
- `/auth/me` ya no rota el CSRF.
- Allowlist con `localhost` y la IP de Tailscale, en el puerto correcto, sin comodines.
- `MAX_CLIENTS = 8`.
- Frontend: **paneles huérfanos** que ningún JS pintaba (Uptime, hero/ECG/mini-kpis, tendencia mensual, `#tasks-status`, `#task-actions`, misión del supervisor, `#tree-wrap`) ahora tienen renderizador; composer habilitado + autoselección de sesión; modelo visible; historial limitado a 100.
- Nexus: `NameError` de `limit` en `vault_search` (daba 500) corregido. Memoria: `not_configured` en vez de `unavailable`.

### Verificación en vivo

- SSE por socket: `HTTP/1.1 200 OK` + chunked + heartbeat cada 5 s.
- `POST` del chat sin modelo → **202** con `model {providerID: opencode-go, modelID: deepseek-v4.1-flash}` y **el asistente respondió** (confirmado leyendo `/session/{id}/message` en el upstream).
- **101 tests OK** + `validate.py` OK (5 tests actualizados: el comportamiento correcto cambió).

### Lecciones

- **Contar/leer no basta: hay que probar como el cliente real.** El SSE "funcionaba" en mis pruebas Python y no en el navegador; la diferencia era el framing HTTP.
- **Un 2xx puede ser una mentira.** El BFF decía 202 mientras el upstream rechazaba. Nunca reportar éxito sin comprobar la respuesta del upstream.
- **Los mocks de test no definían modelo de sesión** → el BFF debe ser tolerante (adapter sin `.get()` → try/except, no 500).
